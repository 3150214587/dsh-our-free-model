# 三种前端的审查与重建计划

## 审查结论

基线为2026-10-19本地2.5.4及尚未提交的全页赞助横幅改动，已完整备份到D盘。实际浏览器捕获了独立端8页的昼夜对照与窄窗口，插件结合真实React基线和源码审查。

优先问题：插件12个入口无分组、窄面板多排导航占屏；侧栏响应式被后续覆盖推翻；小字、全局发光、扫描纹理影响正文；设置草稿覆盖其他页面的新配置；登录原因丢失、资源加载失败无恢复；密钥复制和长任务取消流程不一致。app.css已有5264行和约920处!important，必须整理而非再叠加。

## 方案选择

1. 保留旧代码只加覆盖：短期快，但无法解决相互覆盖和交互缺陷，不采用。
2. **保留三套历史审美，重建布局/主题组件与前端状态：采用。** 身份延续，能完成较彻底改造并控制功能风险。
3. 统一普通后台或换框架：容易统一，但抹平用户明确风格且扩大回归，不采用。

## 执行分工

- 主控：历史要求核对、真实浏览器基线、产品/设计文档、应用生命周期与错误恢复、赞助主题对齐、测试整合与验收。
- 插件实施：client.js中的插件CSS、导航与页面结构/输入保护；不改广告生成段与后端。
- 桌面主题实施：app.css、components/shell.tsx；替换重复覆盖并保留昼/夜身份。
- 桌面业务交互实施：模型/统计/设置/连接/渠道/概览、基础控件；保留数据语义、请求契约与所有功能。
- 独立审查：实施后复核边界和风险，实际运行相关检查。

## 阶段验收

1. 找问题：形成逐页功能清单、历史风格约束和基线截图。
2. 仔细设计：对齐DESIGN.md的形状、材质、动作和状态，统一信息层次。
3. 优化改进：前端分范围并行落地，主控整合；完整批量浏览器检查后集中修复。
4. 交付：提供三种界面前后证据与实际验证范围，保持未提交、不推送、不发布。
